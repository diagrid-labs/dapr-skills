# Agent Tools Checklist — Python

Apply each rule below to every file in `tool_files` produced by `review-detect-target-agent.md`. The "scope" of every rule is a tool body as defined there: a function decorated with a framework tool decorator (`@tool`, `@function_tool`, `@<agent>.tool` / `@<agent>.tool_plain`), the function wrapped by `FunctionTool(` / `StructuredTool.from_function(`, the `_run` / `forward` method of a tool class, a plain function listed in `tools=[...]`, or a LangGraph node function. In a `mixed` project, apply each rule with the flavor of the file (`file_flavors`); rules marked native-only or wrapper-only skip files of the other flavor.

Rule source: see [`../create-agent-python/REFERENCE.md`](../create-agent-python/REFERENCE.md) — section "Tools".

| Rule id      | Severity | What to detect                                                                                                     | Why it matters                                                                                           | Suggested fix                                                                              |
| ------------ | -------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| DAG-TOOL-001 | critical | Tool performs a non-idempotent mutation (`requests.post`, `httpx.post`, DB insert, file write, `DaprClient().publish_event`, `save_state`, `invoke_method`) without an idempotency key | Tools run as at-least-once workflow activities: a crash or retry after the side effect runs it again.  | Send a stable key on the call: the LLM tool-call id (ADK `ToolContext.function_call_id`, openai_agents `ToolContext.tool_call_id`), LangGraph `Runtime.execution_info`, or an LLM-supplied `idempotency_key` argument.|
| DAG-TOOL-002 | warning  | Tool has no description: no docstring (or a one-word / empty one) and no description passed to the decorator      | The LLM routes tool calls by the tool description; a vague one silently degrades agent behaviour.       | Write a one-line sentence describing what the tool does and when to call it.                |
| DAG-TOOL-003 | warning  | Tool returns an unbounded payload — `return response.json()` or `return rows` with no size guard                   | The full message history is the input to every LLM activity and is stored in workflow state; no wrapper truncates it except HolmesGPT. | Truncate, summarize, or return a reference id the agent can fetch selectively.               |
| DAG-TOOL-004 | warning  | Tool has `except Exception: return "..."` / `except: pass` (swallowed exception)                                   | Most runtimes already catch tool exceptions and return the error to the LLM; swallowing hides the failure from the LLM and from retries. | Catch-and-return frameworks: raise. Re-raise frameworks: raise transient errors, return an error value for permanent ones. |
| DAG-TOOL-005 | info     | Tool function parameters are not type-hinted                                                                       | The framework-generated JSON schema is weaker; arg validation degrades.                                  | Add Python type hints for every parameter and a `Field(description=...)` when possible.      |
| DAG-TOOL-006 | warning  | Native only: tool has no `args_model` Pydantic class and accepts free-form `**kwargs`                              | Inputs are unvalidated; malformed tool calls reach the function body instead of being rejected upfront.  | Define a `BaseModel` subclass and pass it via `@tool(args_model=...)`.                      |
| DAG-TOOL-007 | info     | Tool performs a synchronous HTTP call (`requests.get/post`) inside an `async def` tool                              | Each async tool call runs on its own event loop, so only that tool's I/O is serialised.                 | Use `httpx.AsyncClient`, or make the tool a plain `def`.                                    |
| DAG-TOOL-008 | info     | Tool name does not match snake_case or does not clearly express a verb (`data`, `x`, `foo`)                         | Poor naming degrades LLM tool selection.                                                                | Rename to `<verb>_<noun>` (e.g. `get_weather`, `send_invitation`).                         |
| DAG-TOOL-009 | warning  | `print(` used inside a tool instead of `logging`                                                                    | Bypasses structured logging and loses trace correlation.                                                 | Use `logging.getLogger(__name__).info(...)`.                                                |
| DAG-TOOL-010 | warning  | Tool reads or writes module-level mutable globals                                                                   | Tools run on shared workers and parallel tool calls run concurrently; globals leak across invocations and are not thread-safe. | Pass state explicitly, inject dependencies, or store state via a Dapr state component.       |
| DAG-TOOL-011 | critical | Tool constructs an outbound URL (`httpx.`, `requests.`, `urlopen`) from an agent-supplied argument with no allowlist (MCP-sourced tools: see the confidence notes) | Server-side request forgery: the LLM can direct the tool at internal services, cloud metadata endpoints (`169.254.169.254`), or loopback. | Validate the host against an allowlist before the call; block private / link-local / loopback IPs; disable redirect-following. |
| DAG-TOOL-012 | critical | Tool uses an agent-supplied argument as a file path (`open`, `pathlib.Path`, `os.path.join`) without a root-directory check | Path traversal: agent input `../../../etc/passwd` escapes the intended directory. | Resolve the path against an allowed root and assert the resolved path is still inside the root. Reject symlinks that resolve outside. |
| DAG-TOOL-013 | warning  | Tool returns externally-sourced content (HTTP response body, DB row, user-controlled store, MCP tool result) directly to the agent | Prompt injection: adversarial content in the response can override the agent's instructions on the next turn. | Sanitise, truncate, or wrap the content in a typed Pydantic model; strip instruction-like prefixes (e.g. `"IGNORE PREVIOUS..."`). |
| DAG-TOOL-016 | warning  | Wrapper only: tool shape the wrapper cannot execute — pydantic_ai `@agent.tool` whose first parameter is `RunContext`; a plain function in the langchain runner's `tools=`; a claude_agents plain function in `tools=` | The runner calls pydantic_ai tools as `function(**args)` with no context (every call fails); the langchain runner reads `tool.name` at construction; claude_agents advertises a plain function with an empty description and no parameters. | Use `@agent.tool_plain` (or drop `RunContext`); decorate with `langchain_core.tools.tool`; define the tool with `claude_agent_sdk.tool("name", "description", schema)`. |
| DAG-TOOL-017 | info     | Wrapper only: tool returns a non-JSON-native value (`datetime`, `Decimal`, `set`, `bytes`, dataclass, custom class), or a pydantic_ai / claude_agents plain-function tool has parameters typed with such a type | Wrappers keep `str`/number/`bool`/`list`/`dict`/`None` and Pydantic models, and turn anything else into `str(value)`; parameters receive raw JSON values, and unparseable arguments become `{}`. | Return a `dict` or a Pydantic model; take JSON-native parameters and convert inside the tool. |
| DAG-TOOL-018 | info     | Wrapper only: tool or agent code expects configurable durable retries (a framework retry option on a tool, or a comment / docstring stating a retry count) | Wrappers hardcode `RetryPolicy(3 attempts, 1s first interval, x2 backoff, 30s max)` on every activity, and the Strands runner and `DurableAgent` set none; catch-and-return frameworks never retry a tool exception. | Make the tool safe under the fixed policy (idempotent, raise only transient errors) and document the actual retry behaviour. |

## Framework error behaviour (DAG-TOOL-004)

- **Catch-and-return** — native `dapr_agents`, adk, claude_agents, crewai, openai_agents, pydantic_ai, strands: the tool activity catches the exception and returns its message to the LLM as the tool result. `Fix:` raise (or let the exception propagate).
- **Re-raise** — langchain, smolagents, langgraph, deepagents: the tool exception fails the activity, which is retried (3 attempts) and then fails the workflow. `Fix:` raise only transient errors; return an error value the LLM can act on for permanent ones (validation, not found).

Name the framework of the file (`wrapper_frameworks`, or native) in the `Fix:` line.

## Confidence notes

- DAG-TOOL-001 — Idempotency may appear as an `Idempotency-Key` header, a key passed as an argument, or a key derived from a tool-call id or `Runtime.execution_info`. Treat as satisfied if any of these is visible on the outbound call. No Python runtime passes a `taskExecutionId` to a tool. `save_state` that overwrites a fixed key is idempotent; flag it only when the key or value is generated per call (`uuid4()`, a timestamp, an append). `publish_event` and `invoke_method` are flagged unless the payload or metadata carries such a key. Report it as critical: do not move it to Please verify on a guess that the remote service already tolerates repeats (for example that a repeated cancel is a no-op). Only an idempotency mechanism visible in this code satisfies the rule; mention the server-side possibility in `Fix:` if it matters.
- DAG-TOOL-002 — Native `dapr_agents.tool` raises `ToolError` at import time when the docstring is missing entirely, so the agent does not start; still report it under this rule, and cite that consequence in `Why:`. One-word docstrings pass that check and only degrade routing. A description passed to the decorator satisfies the rule (claude_agents `@tool("name", "description", schema)` needs no docstring). crewai `@tool("Some name")` with no docstring: report under Please verify (whether crewai requires a docstring is not settled; the runner falls back to the decorator string when it contains a space). claude_agents plain functions are reported under DAG-TOOL-016, not here.
- DAG-TOOL-005 / DAG-TOOL-006 — Without `args_model`, native `@tool` infers the argument schema from the parameter type hints (untyped parameters become `str`). A tool whose named parameters are all type-hinted is therefore validated and does not trigger DAG-TOOL-006; that rule needs both no `args_model` **and** a `**kwargs` parameter. A missing return-type annotation triggers neither rule. claude_agents `@tool` handlers take one `args` dict whose schema comes from the decorator; skip DAG-TOOL-005 for them.
- DAG-TOOL-007 — Only flag inside `async def` bodies. Synchronous tools are allowed.
- DAG-TOOL-011 / DAG-TOOL-013 — For MCP-sourced tools the tool body is on the MCP server: cite the line that wires the MCP tools into the agent, report DAG-TOOL-013 (the results are external content) and DAG-TOOL-011 under Please verify (URL handling cannot be checked locally).
- DAG-TOOL-016 — Report two further shapes under Please verify only: a langchain `@tool` on an `async def` (async-only) passed to the langchain runner, which invokes tools synchronously; and an ADK plain function in `tools=[...]` instead of `FunctionTool(...)` (the runner reads `tool.name`; whether ADK wraps the function first is not settled).
