# Agent Tools Checklist — .NET

Apply each rule below to every file in `tool_files` produced by `review-detect-target-agent.md`. The "scope" of every rule is a method referenced by `AIFunctionFactory.Create(...)`.

Rule source: see [`agent-tools-dotnet.md`](./agent-tools-dotnet.md) and [`../create-agent-dotnet/REFERENCE.md`](../create-agent-dotnet/REFERENCE.md) — section "Tools/WeatherTools.cs".

| Rule id      | Severity | What to detect                                                                                                                   | Why it matters                                                                                        | Suggested fix                                                                                |
| ------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| DAG-TOOL-001 | critical | Tool performs a non-idempotent mutation (`HttpClient.PostAsync`, DB `ExecuteAsync`, file write) without an idempotency key | Each tool call is a workflow activity, and activities execute at least once: if the process dies after the side effect but before the activity completion is recorded, the tool runs again on recovery. (No retry policy is applied to tool activities.) | Pass an idempotency key as a header or write-key. A stable key is `IDaprAgentContextAccessor.Current.CurrentWorkflowInstanceId` combined with a hash of the tool arguments. |
| DAG-TOOL-002 | warning | Tool has no description: no `[Description]` on the method, no `description:` argument to `AIFunctionFactory.Create(...)`, and no `AIFunctionFactoryOptions.Description` | The LLM routes tools by description; without it, tool routing is guesswork. | Add `[Description("...")]` above the method, or pass `description: "..."` to `AIFunctionFactory.Create`. |
| DAG-TOOL-003 | warning  | Any parameter is missing `[Description]`                                                                                         | The LLM receives an under-specified JSON schema for the tool call.                                   | Add `[Description("...")]` on every parameter.                                                |
| DAG-TOOL-004 | warning  | Tool returns `object`, `dynamic`, or an unbounded collection with no cap                                                         | Unbounded returns bloat agent context and token costs.                                                | Return a concrete typed record; truncate collections before returning.                        |
| DAG-TOOL-005 | warning | Tool has `catch (Exception) { return ...; }` that turns every failure into a magic string or a success-shaped value | Silently turns failures into successes, so the LLM cannot tell what went wrong. (The opposite extreme also hurts: an uncaught exception fails the whole agent run, and `RunAgentAsync` throws.) | Return a typed error record (e.g. `ToolResult(bool Success, string? Error)`) for expected or recoverable failures so the LLM can react; let truly unexpected exceptions throw. |
| DAG-TOOL-006 | warning  | Tool uses `.Result` or `.Wait()` on an async call                                                                                | Sync-over-async deadlocks the agent's execution context.                                             | Mark the tool method `async Task<T>` and `await` the call.                                    |
| DAG-TOOL-007 | info     | Tool method name does not clearly express a verb (`Data`, `X`, `Foo`)                                                            | Poor naming degrades LLM tool selection.                                                             | Rename to `<Verb><Noun>` (e.g. `GetWeather`, `SendInvitation`).                              |
| DAG-TOOL-008 | warning  | `Console.WriteLine` used instead of `ILogger`                                                                                    | Bypasses the application's logging pipeline and trace correlation.                                   | Inject `ILogger<T>` and use structured logging methods.                                       |
| DAG-TOOL-011 | critical | Tool constructs an outbound URL (`HttpClient.GetAsync`, `HttpClient.SendAsync`) from an agent-supplied argument with no allowlist | Server-side request forgery: the LLM can direct the tool at internal services, cloud metadata endpoints, or loopback. | Validate the host against an allowlist before the call; block private / link-local / loopback IPs; set `AllowAutoRedirect = false`. |
| DAG-TOOL-012 | critical | Tool uses an agent-supplied argument as a file path (`File.*`, `Path.Combine`, `new FileStream`) without a root-directory check | Path traversal: agent input `..\\..\\..\\Windows\\System32` escapes the intended directory. | Resolve with `Path.GetFullPath` and assert `resolved.StartsWith(allowedRoot, StringComparison.Ordinal)`. |
| DAG-TOOL-013 | warning  | Tool returns externally-sourced content (HTTP response body, DB row, user-controlled store) directly to the agent | Prompt injection: adversarial content in the response can override the agent's instructions on the next turn. | Return a typed record with bounded size; strip instruction-like prefixes before returning. |
| DAG-TOOL-014 | warning | `AIFunctionFactory.Create(...)` called without `name:` on a method whose name differs from the tool name used in the agent's `instructions` (e.g. method `GetWeatherImpl`, instructions say "GetWeather") | The LLM sees the method name, so instructions that reference another name make it call a tool that does not exist; the run then fails with "Tool '…' not found in registry". | Pass `name: "<ToolName>"` to `AIFunctionFactory.Create`, or rename the method. |
| DAG-TOOL-015 | warning | A tool is wrapped in `ApprovalRequiredAIFunction` (or the agent uses `WithSkills(...)`) but no `IToolApprovalHandler` is registered **before** `AddDaprAgents()` | `AddDaprAgents()` registers a `DenyingToolApprovalHandler` with `TryAddSingleton`; without a handler registered earlier, every gated call is denied and the LLM only receives `{approved: false}`. | Register a custom `IToolApprovalHandler` with `builder.Services.AddSingleton<IToolApprovalHandler, MyApprovalHandler>()` before calling `AddDaprAgents()`. |

## Confidence notes

- DAG-TOOL-001 — Idempotency may appear as a header (e.g. `Idempotency-Key`), a parameter the caller passes in, or a deterministic id (e.g. `IDaprAgentContextAccessor.Current.CurrentWorkflowInstanceId` + argument hash). Any of these satisfy the rule.
- DAG-TOOL-002 — A description passed as the third argument of `AIFunctionFactory.Create(method, name, description)` satisfies the rule; this is the style used by the `diagridio/dotnet-ai` examples.
- DAG-TOOL-014 and DAG-TOOL-015 are .NET-only ids (Python uses `DAG-TOOL-009` and `DAG-TOOL-010` for Python-only rules).
