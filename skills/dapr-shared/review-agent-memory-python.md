# Agent Memory Checklist — Python

Apply each rule below to every file in `agent_files` + `component_files` produced by `review-detect-target-agent.md`.

Rule source: see [`../create-agent-python/REFERENCE.md`](../create-agent-python/REFERENCE.md) — section "Memory and state". Native claims are checked against `dapr-agents` 1.0.9, wrapper claims against `diagrid` 0.5.3.

**Read this before applying the rules.**

- **Flavor per file.** The Flavor column says which files a rule applies to: `native` (the file imports `dapr_agents`), `wrapper` (the file imports `diagrid.agent.`), or `all` (component YAMLs and every agent file). In a `mixed` project (for example a native coordinator with wrapper specialists), apply each rule to a file according to that file's own imports. A `DurableAgent(` call is native only when its file imports `dapr_agents`; `diagrid.agent.strands.DurableAgent` is a wrapper.
- **Native memory is per run.** `ConversationDaprStateMemory` keys history as `{agent}:_memory_{workflow_instance_id}`, so it never carries across runs. At construction the agent reads the sidecar metadata and auto-wires `state` from a state component named exactly `agent-workflow` and `memory` from one named exactly `agent-memory` (each only when the keyword is omitted). Whenever `state` is set (explicitly or auto-wired), any memory store is replaced by `ConversationDaprStateMemory` on the **state** store, so an explicit `memory=` and the `agent-memory` component are then unused. With no `state`, memory falls back to `memory=`, then `agent-memory`, then in-process `ConversationListMemory`.
- **Wrappers keep no conversation store.** A `diagrid` runner keeps history in the workflow instance only, and each `/agent/run` call starts a new instance (a reused `session_id`/`thread_id` only prefixes the instance id). The runner's `state_store=` (or the auto-discovered `agent-memory`) is only published as metadata in the agent registry. Cross-run memory needs a framework helper (`DaprMemoryStore`, `DaprSessionStore`, `DaprMemoryCheckpointer`, `DaprStateSessionManager`) that the app's own code calls. Helper default stores: `statestore`, except `DaprMemoryCheckpointer` (langgraph) and `DaprStateSessionManager` (strands), which default to `agent-memory`; HolmesGPT uses `HOLMES_EVENTS_STORE` (default `statestore`).
- **Resources.** When `dapr.yaml` sets `resourcesPath`, the default `dapr init` components (including `statestore`) are not loaded; only the files in that folder exist. Catalyst projects use managed components: skip DAG-MEM-001, -009 and -012 when there is no local resources folder and the project targets Catalyst.

## Confidence notes

- DAG-MEM-001 — Skip when the project has no resources folder and `dapr.yaml` sets no `resourcesPath` (the `dapr init` `statestore` is the actor store then). DAG-MEM-001 and DAG-MEM-009 never fire together: count the components with `actorStateStore: "true"` — zero is DAG-MEM-001, two or more is DAG-MEM-009, exactly one is neither.
- DAG-MEM-002 — If the agent has `state=`, or an `agent-workflow` state component exists, report under "Please verify" instead: the `ConversationListMemory` is ineffective, because memory is replaced by `ConversationDaprStateMemory` on the state store. Also downgrade to "Please verify" when the file has explicit dev-only comments (e.g. `# dev memory only`) or lives in an `examples/` folder.
- DAG-MEM-003 detection is specific: the `value:` of a metadata entry whose `name:` is `key` (or `apiKey`, `accessToken`, `password`) must match `^"{{[A-Z_]+}}"$` (literal templating) or use `secretKeyRef:` on the same entry. Any other value triggers the rule. Bypass shapes to treat as "Please verify":
  - Commented-out plaintext keys elsewhere in the file (grep `^\s*#\s*value:\s*['"]?sk-`) — the commented value is not active but the intent is suspicious.
  - Base64-encoded values (`^[A-Za-z0-9+/=]{40,}$` without `{{...}}` templating) — may be a real key or an opaque identifier.
  - YAML anchors (`&` / `*`) resolving to a hardcoded string defined elsewhere in the file.
  - Provider key shapes to watch for: OpenAI `sk-`, `sk-proj-`; Anthropic `sk-ant-`; Google `AIza`; Azure `{apiKey}` pattern.
- DAG-MEM-006 — When there is no `state=` but an `agent-workflow` state component exists, report under "Please verify" instead ("relies on auto-wiring from `agent-workflow`"): verify the component is loaded for this app (no `scopes:` that exclude it) and the sidecar is up when the agent is constructed.
- DAG-MEM-008 — Do not flag `keyPrefix: name` (the prefix is the shared component name); list it under "Please verify". The need for `keyPrefix: none` is inferred from the `dapr-agents` component YAMLs and the shared `agents:<team>:...` key layout, not from documentation.
- DAG-MEM-009 — Report under "Please verify" ("confirm against the targeted Dapr runtime that a second actor state store fails startup") until confirmed for Dapr 1.18.
- DAG-MEM-010 — Without git access, "committed" means "present in scope and not excluded by `.gitignore`". Placeholder values (`your-key-here`, `sk-...`, empty) are not findings.
- DAG-MEM-011 — `DaprStateSessionManager` (strands) is a hook provider that loads and saves on its own when passed in an agent's `hooks=[...]`; whether the strands runner fires those hooks is unverified, so list a hooked session manager under "Please verify" instead.
- DAG-MEM-013 — A module-level constant (`AGENT_NAME = "triage"`) passed as `name=` is a literal. A name read from configuration that never changes in practice is "Please verify".
